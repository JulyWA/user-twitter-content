# KOL 文档格式规范

更新时间：2026-05-14

这个仓库里每个 KOL 至少维护两类人工可读文档：

- `report.md`：账号级知识报告，回答“这个账号对我的知识库有什么用”。
- `research_logic.md`：投研逻辑沉淀，回答“这个人判断项目时看什么信号、怎么否决、怎么使用”。

## report.md 标准结构

### 数据卡

必须包含：

- Handle 和 X 链接
- 是否蓝 V / verified_or_above
- 粉丝数
- 已归档推文数
- 入库知识记录数
- 仅保留链接记录数
- RT/转推占比或使用提醒

### 一句话画像

用 1-3 句话说明这个 KOL 的核心价值。不要写空泛标签，要能说明具体适用场景。

### 可用场景

列出适合用这个账号辅助判断的问题，例如：

- Meme 是否处在周期尾部？
- DeFi 协议收入是否能捕获到代币？
- 某个 AI 基建标的是不是处在利润池？

### 不适合场景

列出这个账号不应该被单独使用的场景。比如短线交易账号不适合直接做长期价值判断；转推占比高的账号不能把所有观点都归因给本人。

### 主题地图

用表格列出 4-6 个主题：

- 主题
- 这个主题里可沉淀的内容
- 证据链接
- 使用方式

### 代表证据

至少列出 5 条证据链接。证据要尽量区分：

- 原创观点
- 转推/引用观点
- 交易复盘
- 风险提醒
- 项目判断

### 如何用于项目研究

给出 5-8 步具体使用方法，最好能直接转化为项目研究 checklist。

### 写作风格

总结语言风格、结构方式、适合模仿的内容类型。

### 人工复核提醒

说明这份报告的局限，例如：

- API 只返回分页窗口，不保证账号注册以来全历史。
- 规则筛选可能误判噪音。
- RT 内容需要追溯原作者。
- 某些结论需要人工阅读原文全文后确认。

## research_logic.md 标准结构

### 核心模型

用一句话或一个小框架说明该 KOL 的底层判断模型。

### 重要信号矩阵

必须包含：

- 信号
- 观察方式
- 为什么重要
- 证据链接
- 项目研究时怎么用

### 否决信号矩阵

必须包含：

- 否决信号
- 说明
- 证据链接
- 触发后的动作

### 使用流程

给出可执行流程，而不是只写结论。建议格式：

1. 先看什么。
2. 再排除什么。
3. 如何找证据。
4. 如何形成判断。
5. 何时放弃。

### 与其他 KOL 的互补

说明这个 KOL 应该和谁组合使用，形成什么双重验证。

### 可转化为问题库

把他的投研逻辑转成 6-10 个问题，方便未来做项目研究模板。

### 样本限制

说明：

- 本文基于当前抓取窗口。
- 是否有较高 RT 比例。
- 哪些结论仍需要人工复核。

## 命名和维护规则

- 所有正文用中文。
- 所有判断尽量挂原文链接。
- 不能只写“有价值”，必须说明“什么价值、怎么用”。
- `report.md` 更偏账号说明；`research_logic.md` 更偏方法论和 checklist。
- 新增 KOL 时先生成简版可以接受，但进入正式知识库前必须升级到本规范。
