# KOL 文档格式规范

更新时间：2026-05-15

这个仓库里每个 KOL 至少维护两类人工可读文档：

- `report.md`：账号级知识报告，回答“这个账号能提供什么机会线索、适合什么研究场景”。
- `research_logic.md`：机会判断和策略复刻逻辑，回答“这个人看什么信号、如何拆收益来源、怎么排除风险、怎么复刻或改造”。

当前主定位是套利 / 隐藏机会抓取与策略复刻。项目投研画像可以保留为辅助资料，但不再是文档默认目标。

## report.md 标准结构

### 数据卡

必须包含：

- Handle 和 X 链接
- 是否蓝 V / verified_or_above
- 粉丝数
- 已归档推文数
- 入库知识记录数
- 仅保留链接记录数
- RT/转推占比或使用提醒

### 一句话画像

用 1-3 句话说明这个 KOL 的核心价值。不要写空泛标签，要能说明具体适用场景。

### 可用场景

列出适合用这个账号辅助判断的问题，例如：

- 是否存在资金费率 / 价差 / 基差套利？
- 某个积分或空投机会能否与对冲现金流结合？
- 带图推文里有哪些可复刻监控字段？
- 某个 DeFi 收入、APR 或 LP 机会的真实风险在哪里？

### 不适合场景

列出这个账号不应该被单独使用的场景。比如短线交易账号不适合直接做长期价值判断；转推占比高的账号不能把所有观点都归因给本人。

### 主题地图

用表格列出 4-6 个主题：

- 主题
- 这个主题里可沉淀的机会或方法
- 证据链接
- 使用方式

### 代表证据

至少列出 5 条证据链接。证据要尽量区分：

- 原创观点
- 转推/引用观点
- 交易复盘
- 策略截图或监控面板
- 风险提醒
- 项目判断或机会判断

### 如何用于机会研究

给出 5-8 步具体使用方法，最好能直接转化为机会研究或策略复刻 checklist。

### 写作风格

总结语言风格、结构方式、适合模仿的内容类型。

### 人工复核提醒

说明这份报告的局限，例如：

- API 只返回分页窗口，不保证账号注册以来全历史。
- 规则筛选可能误判噪音。
- RT 内容需要追溯原作者。
- 某些结论需要人工阅读原文全文后确认。

## research_logic.md 标准结构

### 核心模型

用一句话或一个小框架说明该 KOL 的底层机会判断模型。

### 重要机会信号矩阵

必须包含：

- 信号
- 观察方式
- 为什么重要
- 证据链接
- 机会研究时怎么用

套利和隐藏机会类 KOL 需要优先写清：

- 收益来源
- 交易腿 / 对冲腿
- 交易场所
- 监控字段
- 成本和滑点
- 可执行规模
- 风险触发条件

### 否决信号矩阵

必须包含：

- 否决信号
- 说明
- 证据链接
- 触发后的动作

### 使用流程

给出可执行流程，而不是只写结论。建议格式：

1. 先看什么。
2. 再排除什么。
3. 如何找证据。
4. 如何形成判断。
5. 何时放弃。

### 与其他 KOL 的互补

说明这个 KOL 应该和谁组合使用，形成什么交叉验证。

### 可转化为问题库

把他的机会判断逻辑转成 6-10 个问题，方便未来做策略研究模板。

### 可复刻策略字段

如果账号经常分享套利、量化、监控面板或带图策略，必须单独列出：

- 可复刻策略类型
- 需要的数据源
- 需要监控的字段
- 可以自动化的部分
- 必须人工确认的部分
- 已过期或高风险的部分

### 样本限制

说明：

- 本文基于当前抓取窗口。
- 是否有较高 RT 比例。
- 哪些结论仍需要人工复核。

## 命名和维护规则

- 所有正文用中文。
- 所有判断尽量挂原文链接。
- 不能只写“有价值”，必须说明“什么价值、怎么用”。
- `report.md` 更偏账号说明；`research_logic.md` 更偏方法论和 checklist。
- 新增 KOL 时先生成简版可以接受，但进入正式知识库前必须升级到本规范。
- 旧项目评分只作为历史材料，不再作为新增文档的默认结构。
